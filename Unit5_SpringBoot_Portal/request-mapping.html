Request Mapping in Spring MVC

Connect HTTP methods, paths, headers, parameters, and media types to the correct controller handler.

← Previous: REST Controller Unit 5 Home Next: Request Body →

Learning outcomes

After this lesson, you should be able to compose class-level and method-level mappings, constrain handlers by HTTP method, path, parameters, headers, and media type, recognize mapping conflicts, and diagnose common HTTP mapping errors.

Mapping principle: A handler should match the request characteristics that define its operation. Make routes specific and unambiguous instead of relying on method declaration order.

1. How Spring selects a handler

At startup, Spring MVC discovers annotated controller methods and registers their mapping conditions. At runtime, the dispatcher compares an incoming request with those conditions and invokes the matching handler through the MVC infrastructure.

The DispatcherServlet is Spring MVC’s front controller. Handler mapping infrastructure identifies a suitable controller method; argument resolvers and message converters prepare its parameters; return-value handling builds the response. Exceptions can be translated by controller advice or other exception resolvers.

2. Mapping annotations

@RequestMapping is the general mapping annotation. Composed annotations express common HTTP methods more clearly:

AnnotationHTTP methodTypical purpose
@GetMappingGETRead a resource or collection.
@PostMappingPOSTCreate a resource or submit a command.
@PutMappingPUTReplace a resource at a known URI.
@PatchMappingPATCHApply a partial update.
@DeleteMappingDELETEDelete a resource.
@RequestMappingAny or configured methodShared prefixes or less common mapping conditions.

These are composed forms of @RequestMapping. Use the specific annotations for ordinary CRUD endpoints so the method semantics are visible in the code.

3. Compose class and method paths

A class-level mapping commonly defines the resource prefix; the method-level mapping adds a subpath. For example, @RequestMapping("/api/courses") combined with @GetMapping("/{courseId}") matches GET /api/courses/42.

@RestController
@RequestMapping("/api/courses")
public class CourseController {
    @GetMapping
    public List<CourseResponse> listCourses() {
        return courseService.findAll();
    }

    @GetMapping("/{courseId}")
    public CourseResponse getCourse(
            @PathVariable long courseId) {
        return courseService.findById(courseId);
    }

    @PostMapping
    public ResponseEntity<CourseResponse> createCourse(
            @RequestBody CreateCourseRequest request) {
        CourseResponse created = courseService.create(request);
        return ResponseEntity.status(HttpStatus.CREATED).body(created);
    }
}

Path variable names can be inferred when the Java compiler preserves parameter names and the framework can discover them. Naming them explicitly—for example @PathVariable("courseId")—makes the binding contract clear and robust across compiler settings.

4. Mapping conditions

Spring can match a handler using more than the URL. A request mapping may specify a path, method, query parameter conditions, header conditions, consumes, and produces.

@PostMapping(
    path = "/imports",
    consumes = "application/json",
    produces = "application/json",
    params = "mode=validate"
)
public ImportResult validateImport(
        @RequestBody ImportRequest request,
        @RequestHeader("X-Request-Id") String requestId) {
    return importService.validate(request, requestId);
}
ConditionWhat it matchesCommon mismatch
methodHTTP verb such as GET or POST.Calling a POST-only route with GET can produce 405 Method Not Allowed.
paramsQuery/form parameters that must be present, absent, or equal a value.Missing or unequal required parameter means this mapping is not selected.
headersRequired or constrained request headers.Required header absent or not matching.
consumesMedia type of the incoming request body, typically from Content-Type.Unsupported request format can result in 415 Unsupported Media Type.
producesResponse media types acceptable to the client, using Accept.No compatible representation can result in 406 Not Acceptable.

Do not add conditions just because they are available. Add them when they are part of the endpoint contract and document required parameters and media types for clients.

5. URI path patterns

  • Literal segment: /api/courses/current matches that exact segment.
  • Path variable: /api/courses/{id} captures a segment for a handler parameter.
  • Regex-constrained variable: /api/courses/{id:[0-9]+} restricts the captured segment to digits.
  • Single-segment wildcard: * matches within a path segment.
  • Multi-segment wildcard: ** can match multiple path segments; place it according to Spring’s path-pattern rules and avoid overly broad routes.

Prefer explicit, resource-oriented paths. Overlapping patterns can make matching harder to reason about; a literal route such as /current and a variable route such as /{id} should be designed and tested together.

6. Mapping decision example

For a request to POST /api/courses?mode=validate with Content-Type: application/json and Accept: application/json, Spring evaluates all declared mapping conditions. A candidate handler is eligible only when its path, method, parameter, header, and media-type conditions match.

7. Diagnose common mapping errors

SymptomLikely causeWhat to inspect
404 Not FoundNo registered mapping matches the request path and conditions, or the resource itself is absent.Class/method path composition, context path, active controller scan, and required conditions.
405 Method Not AllowedPath exists, but the request uses an unsupported HTTP method.Use the intended verb; check the method-specific mapping.
415 Unsupported Media TypeRequest Content-Type does not match the handler’s consumes condition or available converter.Set the correct content type and ensure a converter is available.
406 Not AcceptableClient Accept header is incompatible with the handler’s produces condition.Request a supported response type or adjust the declared media types.
Ambiguous mapping at startupTwo handler methods register indistinguishable mappings.Make method, path, params, headers, or media-type conditions distinct.
Handler runs but receives an unexpected valueBinding name, optionality, or converter expectation differs from the request.Check annotation names, Java parameter names, request values, and content type.

Enable targeted Spring MVC mapping diagnostics during local development when necessary. Avoid leaving verbose framework logs enabled in production without a specific operational need.

8. Test request mappings

Test the mapping contract with MockMvc: verify that the intended method and path reach the right handler, and that unsupported methods or media types produce the expected result. The service can be mocked so the test focuses on the web layer.

mockMvc.perform(get("/api/courses/42")
        .accept(MediaType.APPLICATION_JSON))
    .andExpect(status().isOk())
    .andExpect(jsonPath("$.id").value(42));

mockMvc.perform(post("/api/courses")
        .contentType(MediaType.APPLICATION_JSON)
        .content("{\"code\":\"CS336B\",\"title\":\"OOPS with Java\"}"))
    .andExpect(status().isCreated());

Include tests for required query parameters or headers, consumes/produces behavior, overlapping routes, and path-variable conversion failures. Mapping tests catch contract regressions before clients encounter them.

Interview questions

  1. What does a class-level @RequestMapping do?
    It defines shared mapping conditions, commonly a path prefix, for handler methods in the controller.
  2. How does @GetMapping relate to @RequestMapping?
    It is a composed annotation that declares a request mapping constrained to the GET method.
  3. What is the difference between consumes and produces?
    consumes constrains the incoming request representation; produces constrains the response representation acceptable to the client.
  4. What causes an ambiguous mapping?
    Two or more controller methods register equivalent mapping conditions, leaving Spring unable to choose a unique handler.
  5. When is @RequestParam preferable to a path variable?
    For optional filters, pagination, sorting, or modifiers that do not identify the resource itself.
  6. What does the DispatcherServlet do?
    It acts as Spring MVC’s front controller, coordinating handler selection and request/response processing.
