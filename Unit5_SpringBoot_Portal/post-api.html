Unit 5 · Spring Boot & RESTful Web Services

Building a POST API

Create resources safely with Spring Boot, validated JSON input, database persistence, and correct HTTP responses.

← Previous: GET API Unit 5 Home Next: PUT API →

Learning outcomes

After this lesson, you should be able to create a POST endpoint, receive and validate JSON using a request DTO, persist a new resource through service and repository layers, return 201 Created with a resource location, and test successful and rejected requests.

POST is not generally idempotent. Repeating a create request may create another resource. For retryable operations, define duplicate handling or an idempotency-key strategy rather than assuming clients will send a request only once.

1. POST request lifecycle

A POST request normally sends a representation in the body. Spring converts the JSON to a request DTO, validates it, and passes it to application logic. If creation succeeds, the server returns a success status and identifies the new resource.

2. HTTP contract for resource creation

A typical request sends JSON with Content-Type: application/json. A successful create commonly returns 201 Created, a response representation, and a Location header pointing to the new resource.

POST /api/courses HTTP/1.1
Content-Type: application/json
Accept: application/json

{
  "code": "CS336B",
  "title": "OOPS with Java",
  "credits": 4
}
StatusMeaning in a POST API
201 CreatedResource was created; include its location when practical.
200 OKOperation succeeded and a response body is returned, but creation semantics may be less explicit.
202 AcceptedWork was accepted for asynchronous processing and is not yet complete.
400 Bad RequestMalformed JSON, conversion failure, or invalid request fields.
409 ConflictRequest conflicts with current state, such as a duplicate unique course code.
415 Unsupported Media TypeRequest body format is not supported by the endpoint.

4. Define request and response DTOs

A request DTO limits what the client can set. Do not bind a JPA entity directly from untrusted input: that can accidentally expose or allow modification of IDs, roles, ownership, or audit fields.

package com.example.course.dto;

import jakarta.validation.constraints.Max;
import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.Size;

public record CreateCourseRequest(
        @NotBlank
        @Size(max = 20)
        String code,

        @NotBlank
        @Size(max = 120)
        String title,

        @Min(1)
        @Max(6)
        int credits
) {}
package com.example.course.dto;

public record CourseResponse(
        long id,
        String code,
        String title,
        int credits
) {}

Use a response DTO to control the public representation. The client does not choose the generated ID; the server creates and returns it.

5. Persist the resource

This example uses JPA. A database uniqueness constraint is essential even if the service checks for duplicates: two concurrent requests can both pass an application-level check before either inserts.

package com.example.course.entity;

import jakarta.persistence.Column;
import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.persistence.Table;

@Entity
@Table(name = "courses")
public class Course {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, unique = true, length = 20)
    private String code;

    @Column(nullable = false, length = 120)
    private String title;

    @Column(nullable = false)
    private int credits;

    protected Course() {
    }

    public Course(String code, String title, int credits) {
        this.code = code;
        this.title = title;
        this.credits = credits;
    }

    public Long getId() { return id; }
    public String getCode() { return code; }
    public String getTitle() { return title; }
    public int getCredits() { return credits; }
}
package com.example.course.repository;

import com.example.course.entity.Course;
import org.springframework.data.jpa.repository.JpaRepository;

public interface CourseRepository extends JpaRepository<Course, Long> {
    boolean existsByCode(String code);
}

In production, use schema migrations such as Flyway or Liquibase to manage database constraints and schema evolution. Do not depend on automatic schema creation as a migration strategy.

6. Implement creation in the service layer

The service owns the creation use case: apply business rules, persist the entity, and map it to the response DTO. The transaction keeps the write operation within a consistent database boundary.

package com.example.course.service;

import com.example.course.dto.CourseResponse;
import com.example.course.dto.CreateCourseRequest;
import com.example.course.entity.Course;
import com.example.course.exception.DuplicateCourseCodeException;
import com.example.course.repository.CourseRepository;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
public class CourseService {
    private final CourseRepository repository;

    public CourseService(CourseRepository repository) {
        this.repository = repository;
    }

    @Transactional
    public CourseResponse create(CreateCourseRequest request) {
        String normalizedCode = request.code().trim();
        if (repository.existsByCode(normalizedCode)) {
            throw new DuplicateCourseCodeException(request.code());
        }

        Course course = new Course(
                normalizedCode,
                request.title().trim(),
                request.credits());

        Course saved = repository.saveAndFlush(course);
        return toResponse(saved);
    }

    private CourseResponse toResponse(Course course) {
        return new CourseResponse(
                course.getId(),
                course.getCode(),
                course.getTitle(),
                course.getCredits());
    }
}

The unique database constraint remains the final authority when concurrent requests race. The application-level check improves the common response path, but it cannot prevent that race. Handle a database integrity violation at the API boundary as a generic conflict or inspect the violated constraint using database-aware translation; do not claim every integrity failure is necessarily a duplicate code.

Define the domain exception

package com.example.course.exception;

public class DuplicateCourseCodeException extends RuntimeException {
    public DuplicateCourseCodeException(String code) {
        super("A course with code " + code + " already exists");
    }
}

7. Create the controller endpoint

Use @Valid to trigger request DTO validation. Build a resource URI and return it through the Location header with 201 Created.

package com.example.course.controller;

import java.net.URI;

import com.example.course.dto.CourseResponse;
import com.example.course.dto.CreateCourseRequest;
import com.example.course.service.CourseService;
import jakarta.validation.Valid;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;
import org.springframework.web.servlet.support.ServletUriComponentsBuilder;

@RestController
@RequestMapping("/api/courses")
public class CourseController {
    private final CourseService courseService;

    public CourseController(CourseService courseService) {
        this.courseService = courseService;
    }

    @PostMapping
    public ResponseEntity<CourseResponse> create(
            @Valid @RequestBody CreateCourseRequest request) {
        CourseResponse created = courseService.create(request);
        URI location = ServletUriComponentsBuilder
                .fromCurrentRequest()
                .path("/{id}")
                .buildAndExpand(created.id())
                .toUri();

        return ResponseEntity.created(location).body(created);
    }
}

The resulting response has status 201 Created, a Location: /api/courses/{id} header, and the created resource representation in its body.

8. Handle validation and duplicate errors

Map expected client errors to clear 4xx responses. Spring’s ProblemDetail provides a standard error representation on supported Spring versions.

import com.example.course.exception.DuplicateCourseCodeException;
import org.springframework.dao.DataIntegrityViolationException;
import org.springframework.http.HttpStatus;
import org.springframework.http.ProblemDetail;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

@RestControllerAdvice
public class ApiExceptionHandler {
    @ExceptionHandler(DuplicateCourseCodeException.class)
    ProblemDetail handleDuplicate(DuplicateCourseCodeException exception) {
        ProblemDetail problem =
                ProblemDetail.forStatus(HttpStatus.CONFLICT);
        problem.setTitle("Course code already exists");
        problem.setDetail("Choose a different course code.");
        return problem;
    }

    @ExceptionHandler(DataIntegrityViolationException.class)
    ProblemDetail handleConstraintConflict(
            DataIntegrityViolationException exception) {
        ProblemDetail problem =
                ProblemDetail.forStatus(HttpStatus.CONFLICT);
        problem.setTitle("Request conflicts with existing data");
        problem.setDetail("Review the resource values and try again.");
        return problem;
    }
}

Malformed JSON and Bean Validation failures are normally client errors. Avoid returning raw exception messages, database details, or stack traces to clients. Log unexpected server failures with appropriate context and keep error response formats consistent.

9. Test the POST endpoint

Test the HTTP contract, not just the service method. Cover valid JSON, invalid fields, duplicate codes, returned status, response body, and the Location header.

mockMvc.perform(post("/api/courses")
        .contentType(MediaType.APPLICATION_JSON)
        .accept(MediaType.APPLICATION_JSON)
        .content("""
            {"code":"CS336B","title":"OOPS with Java","credits":4}
            """))
    .andExpect(status().isCreated())
    .andExpect(header().string(
            "Location", endsWith("/api/courses/42")))
    .andExpect(jsonPath("$.id").value(42))
    .andExpect(jsonPath("$.code").value("CS336B"));

Also test blank or oversized values, malformed JSON, unsupported content types, duplicate values, and authorization failures. Use a test database or repository mocks depending on whether the test is a web slice or an integration test.

10. Call the API

Start the application and send a JSON request:

./mvnw spring-boot:run

curl -i \
  -X POST http://localhost:8080/api/courses \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{"code":"CS336B","title":"OOPS with Java","credits":4}'

Inspect the status line and headers. A successful response should include 201 Created and a Location header. On Windows, use mvnw.cmd spring-boot:run.

11. Security and reliability considerations

  • Validate and authorize: input validation does not establish that the caller is allowed to create the resource.
  • Prevent mass assignment: accept narrow DTOs, not entities with fields the client should not control.
  • Enforce database constraints: application checks alone cannot prevent races or concurrent duplicates.
  • Bound request sizes: limit JSON body size, string lengths, and nested collection sizes.
  • Handle retries: if duplicate creation on retry is unacceptable, define idempotency keys and store their outcome safely.
  • Use HTTPS: protect submitted data in transit.
  • Do not log secrets or full sensitive bodies: log safe identifiers and outcomes, with redaction where required.

Interview questions

  1. What is the common status code for a successful resource creation?
    201 Created, often with a Location header identifying the new resource.
  2. What does @RequestBody do in a POST endpoint?
    It asks Spring MVC to deserialize the request body into the declared Java type using a message converter.
  3. What does @Valid do?
    It triggers Bean Validation constraints declared on the request DTO.
  4. Why use request DTOs instead of entities?
    DTOs define the public contract and prevent clients from setting internal or privileged fields.
  5. Why keep a unique database constraint if the service checks for duplicates?
    Concurrent requests can pass the application check simultaneously; the database constraint enforces uniqueness atomically.
  6. Is POST idempotent?
    Not generally. Repeated requests may create multiple resources unless the API defines deduplication or idempotency behavior.
