What you will build

In this tutorial, you will create a small Course Portal that displays a course catalog and lets users filter courses by code, title, or description. Spring MVC handles HTTP requests, a service provides catalog data, and Thymeleaf renders HTML on the server.

Technology choices: Maven project · Spring Web · Thymeleaf · Java · executable JAR. This beginner project uses in-memory sample data so you can run it without configuring a database.

Step 1: Generate a Maven project with Spring Initializr

  1. Open Spring Initializr.
  2. Choose Project: Maven and Language: Java.
  3. Select the current stable Spring Boot version offered by Initializr (avoid snapshot versions for this exercise).
  4. Set Group to com.example, Artifact to course-portal, and Name to course-portal.
  5. Choose Packaging: Jar and the Java version supported by both your installed JDK and the Spring Boot version shown by Initializr.
  6. Add dependencies: Spring Web and Thymeleaf. Add Spring Boot DevTools only if you want development-time restart support.
  7. Generate the project, download the ZIP, extract it, and open the extracted course-portal folder in your IDE.

Initializr creates the Maven build file, application entry point, test structure, and Maven Wrapper scripts. Keep the generated Spring Boot version and dependency management; do not copy version numbers from an unrelated project.

Step 3: Confirm the application entry point

Initializr generates a main class. It should be in the root package above the controller and service packages, so Spring’s component scan can discover them.

package com.example.courseportal;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class CoursePortalApplication {
    public static void main(String[] args) {
        SpringApplication.run(CoursePortalApplication.class, args);
    }
}

@SpringBootApplication enables auto-configuration and component scanning in the application package and its subpackages.

Step 4: Create a course model

Create src/main/java/com/example/courseportal/course/Course.java. A Java record gives this read-only sample a concise immutable data type.

package com.example.courseportal.course;

public record Course(
        String code,
        String title,
        String description
) {}

Step 5: Add a service for catalog data

Create CourseCatalogService.java in the same course package. Keeping data access and filtering out of the web controller makes each responsibility easier to maintain and test.

package com.example.courseportal.course;

import java.util.List;
import java.util.Locale;
import org.springframework.stereotype.Service;

@Service
public class CourseCatalogService {
    private final List<Course> courses = List.of(
            new Course("CS336B", "OOPS with Java",
                    "Object-oriented programming concepts using Java."),
            new Course("CS210", "Data Structures",
                    "Core data structures and algorithmic thinking."),
            new Course("CS305", "Web Technologies",
                    "Foundations for building web applications.")
    );

    public List<Course> search(String query) {
        if (query == null || query.isBlank()) {
            return courses;
        }

        String normalized = query.trim().toLowerCase(Locale.ROOT);
        return courses.stream()
                .filter(course ->
                        course.code().toLowerCase(Locale.ROOT)
                                .contains(normalized)
                        || course.title().toLowerCase(Locale.ROOT)
                                .contains(normalized)
                        || course.description().toLowerCase(Locale.ROOT)
                                .contains(normalized))
                .toList();
    }
}

This sample is intentionally in memory: data resets when the app restarts. A database-backed project would replace the list with a repository and add a database dependency and configuration.

Step 6: Create a Spring MVC controller

Create CoursePageController.java in the course package. The controller handles the home page request, passes the search results to the model, and returns the template name.

package com.example.courseportal.course;

import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;

@Controller
public class CoursePageController {
    private final CourseCatalogService catalogService;

    public CoursePageController(CourseCatalogService catalogService) {
        this.catalogService = catalogService;
    }

    @GetMapping("/")
    public String home(
            @RequestParam(required = false) String q,
            Model model) {
        model.addAttribute("courses", catalogService.search(q));
        model.addAttribute("query", q == null ? "" : q);
        return "courses";
    }
}

Use @Controller for a page-rendering handler. Unlike @RestController, the returned string is a view name. The Model carries data to the template.

Step 7: Build the Thymeleaf page

Create src/main/resources/templates/courses.html. Thymeleaf expressions render model values into HTML. The th:text attribute writes escaped text, which is safer than inserting untrusted strings as raw HTML.

<!doctype html>
<html lang="en" xmlns:th="http://www.thymeleaf.org">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Course Portal</title>
  <link rel="stylesheet" th:href="@{/styles.css}">
</head>
<body>
  <header class="hero">
    <p class="eyebrow">KIET University · CS &amp; CSE (DS)</p>
    <h1>Course Portal</h1>
    <p>Explore the course catalog.</p>
  </header>

  <main class="content">
    <form method="get" th:action="@{/}" class="search">
      <label for="q">Search courses</label>
      <div class="search-row">
        <input id="q" name="q" type="search"
               th:value="${query}"
               placeholder="Search by code, title, or description">
        <button type="submit">Search</button>
        <a th:href="@{/}">Clear</a>
      </div>
    </form>

    <section class="course-grid" aria-label="Courses">
      <article class="course-card" th:each="course : ${courses}">
        <p class="course-code" th:text="${course.code}">CS336B</p>
        <h2 th:text="${course.title}">OOPS with Java</h2>
        <p th:text="${course.description}">Course description</p>
      </article>
      <p class="empty" th:if="${#lists.isEmpty(courses)}">
        No courses match your search.
      </p>
    </section>
  </main>
</body>
</html>

The form uses GET because searching does not change server state. Submitting a search produces a shareable URL such as /?q=Java.

Step 9: Run the application with Maven

Open a terminal in the project root (the directory containing pom.xml) and use the Maven Wrapper:

# macOS / Linux
./mvnw spring-boot:run

# Windows Command Prompt
mvnw.cmd spring-boot:run

Open http://localhost:8080/ in a browser. Try searching for Java, CS336B, and a term with no match. Stop the application with Ctrl+C.

The wrapper uses the Maven version configured by the project. If the wrapper script is not executable on macOS/Linux, run chmod +x mvnw once, then retry.

Step 10: Add a web-layer test

Initializr commonly adds Spring Boot Starter Test. If it is missing, add this dependency inside the Maven <dependencies> section of pom.xml; Spring Boot’s dependency management supplies its version.

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-test</artifactId>
    <scope>test</scope>
</dependency>

Create a test under src/test/java/com/example/courseportal/course/CoursePageControllerTest.java. This integration-style test starts the application context and checks the rendered page.

package com.example.courseportal.course;

import static org.hamcrest.Matchers.containsString;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.content;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.AutoConfigureMockMvc;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.test.web.servlet.MockMvc;

@SpringBootTest
@AutoConfigureMockMvc
class CoursePageControllerTest {
    @Autowired
    MockMvc mockMvc;

    @Test
    void homePageShowsCourseCatalog() throws Exception {
        mockMvc.perform(get("/"))
                .andExpect(status().isOk())
                .andExpect(content().string(
                        containsString("Course Portal")))
                .andExpect(content().string(
                        containsString("CS336B")));
    }

    @Test
    void searchFiltersCourses() throws Exception {
        mockMvc.perform(get("/").param("q", "Java"))
                .andExpect(status().isOk())
                .andExpect(content().string(
                        containsString("OOPS with Java")))
                .andExpect(content().string(
                        org.hamcrest.Matchers.not(
                                containsString("Data Structures"))));
    }
}

Run the test suite with:

./mvnw test

Step 11: Package and run the executable JAR

Build a production artifact from the project root:

./mvnw clean package
java -jar target/course-portal-0.0.1-SNAPSHOT.jar

The artifact version in the filename comes from the generated pom.xml; check that file and adjust the command if you changed the version. An executable Spring Boot JAR includes the application and its runtime dependencies.

Troubleshooting checklist

  • Whitelabel error or 404: confirm the controller is under the main application package and the route is /.
  • Template not found: put courses.html under src/main/resources/templates and return "courses" from the controller.
  • CSS is missing: put styles.css under src/main/resources/static and link using @{/styles.css}.
  • Port already in use: stop the other process or set server.port in application.properties.
  • Maven cannot resolve dependencies: check network access and inspect the first Maven error; do not suppress dependency failures.
  • Java version error: use a JDK version supported by the selected Spring Boot release and the project’s Maven configuration.

Next steps for a real project

This catalog is intentionally read-only and uses in-memory data. To evolve it:

  1. Add a database driver and Spring Data JPA dependency using Spring Initializr.
  2. Create a JPA entity and repository, then replace the sample list in the service.
  3. Add migrations with Flyway or Liquibase rather than relying on automatic production schema creation.
  4. Add form submission and Bean Validation for creating or editing courses.
  5. Add authentication, authorization, CSRF protection for browser forms, and secure configuration as needed.
  6. Use REST controllers as a separate API contract when other clients need JSON; Thymeleaf pages and REST endpoints can coexist.
