Building a GET API

Retrieve resources and collections with Spring Boot, using clear routes, query parameters, correct HTTP responses, and tests.

← Previous: Request Parameter Unit 5 Home Next: POST API →

Learning outcomes

After this lesson, you should be able to add a GET endpoint to a Spring Boot project, retrieve one resource or a collection, use query parameters for filtering and pagination, choose appropriate responses, and test the endpoint.

GET requests should be safe and idempotent. A GET handler should retrieve data, not create, update, or delete it. Repeating the same request should have no additional state-changing effect.

1. GET request flow

A client sends an HTTP GET request. Spring MVC selects a matching controller method, the application retrieves data, and Spring serializes the returned response into the HTTP representation.

2. Design the GET routes

Use a path variable to identify an item and query parameters to refine a collection request.

PurposeHTTP requestTypical result
List coursesGET /api/courses200 OK with a JSON array or page.
Read one courseGET /api/courses/42200 OK or 404 Not Found.
Filter coursesGET /api/courses?department=CS200 OK with matching results.
Paginate coursesGET /api/courses?page=0&size=20200 OK with a bounded page.

GET requests generally should not require a request body. Put filters in the query string so clients, browsers, and caches can identify the requested representation using the URI.

3. Incorporate a GET API into a Spring Boot project

Step 1: Add the web dependency

For a Maven project, make sure the Spring Boot web starter is present. If the project was created with Spring Initializr and already includes this starter, do not add it a second time.

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>

The web starter supplies Spring MVC and the usual JSON support. A typical source layout is:

src/main/java/com/example/course/
├── CourseApplication.java
├── controller/CourseController.java
├── service/CourseService.java
├── repository/CourseRepository.java
└── dto/CourseResponse.java

Step 2: Define a response DTO

A DTO defines the fields the API exposes. Avoid returning a database entity directly when it contains internal or sensitive fields.

package com.example.course.dto;

public record CourseResponse(
        long id,
        String code,
        String title,
        int credits,
        String department
) {}

Step 3: Put retrieval logic behind a service

This in-memory service makes the example runnable without a database. Data resets when the process restarts; replace it with a repository-backed implementation when persistent storage is required.

package com.example.course.service;

import java.util.List;
import java.util.Optional;

import com.example.course.dto.CourseResponse;
import org.springframework.stereotype.Service;

@Service
public class CourseService {
    private final List<CourseResponse> courses = List.of(
            new CourseResponse(42L, "CS336B",
                    "OOPS with Java", 4, "CS"),
            new CourseResponse(43L, "CS210",
                    "Data Structures", 4, "CS")
    );

    public List<CourseResponse> findAll() {
        return courses;
    }

    public Optional<CourseResponse> findById(long id) {
        return courses.stream()
                .filter(course -> course.id() == id)
                .findFirst();
    }

    public List<CourseResponse> search(String department) {
        if (department == null || department.isBlank()) {
            return findAll();
        }
        return courses.stream()
                .filter(course -> course.department()
                        .equalsIgnoreCase(department))
                .toList();
    }
}

The sample models a department field and filters case-insensitively. In a database-backed application, perform this filtering in the repository query instead of loading every row into memory.

Step 4: Expose controller endpoints

package com.example.course.controller;

import java.util.List;

import com.example.course.dto.CourseResponse;
import com.example.course.service.CourseService;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/api/courses")
public class CourseController {
    private final CourseService courseService;

    public CourseController(CourseService courseService) {
        this.courseService = courseService;
    }

    @GetMapping
    public List<CourseResponse> listCourses(
            @RequestParam(required = false) String department) {
        return courseService.search(department);
    }

    @GetMapping("/{id}")
    public ResponseEntity<CourseResponse> getCourse(
            @PathVariable long id) {
        return courseService.findById(id)
                .map(ResponseEntity::ok)
                .orElseGet(() -> ResponseEntity.notFound().build());
    }
}

Step 5: Run and call it

./mvnw spring-boot:run

curl -i http://localhost:8080/api/courses
curl -i http://localhost:8080/api/courses/42

On Windows, run mvnw.cmd spring-boot:run. With the sample in-memory data, the first route returns both courses as JSON and the second returns the course with ID 42. A missing ID returns 404 Not Found.

4. Replace the demo with a database repository

For persistent data, add the appropriate Spring Data starter and database driver, define a persistence entity and repository, then have the service query the repository. Keep the controller contract independent of persistence details.

public interface CourseRepository
        extends JpaRepository<CourseEntity, Long> {
    List<CourseEntity> findByDepartmentIgnoreCase(String department);
}

A repository-backed service can map entities to DTOs:

@Service
public class CourseService {
    private final CourseRepository repository;

    public CourseService(CourseRepository repository) {
        this.repository = repository;
    }

    public Optional<CourseResponse> findById(long id) {
        return repository.findById(id).map(course ->
                new CourseResponse(course.getId(), course.getCode(),
                        course.getTitle(), course.getCredits(),
                        course.getDepartment()));
    }
}

This repository example assumes a CourseEntity with the shown getters and the Spring Data JPA dependency/configuration. For large collections, use database-side pagination and filtering rather than loading every row into memory.

5. Status codes and response behavior

  • 200 OK: the resource or collection was found and returned.
  • 404 Not Found: the requested item does not exist or is not visible to the caller, according to the API’s disclosure policy.
  • 400 Bad Request: an identifier or query parameter could not be converted or failed validation.
  • 401 Unauthorized / 403 Forbidden: authentication or authorization requirements were not met.

A collection with no matches normally returns 200 OK and an empty collection, not 404. Consider consistent error bodies, documented pagination metadata, and appropriate cache headers for data that can be cached.

6. Filtering and pagination

Collection endpoints should accept bounded filters and pagination where appropriate. Validate the page number, enforce a maximum size, and apply filtering and ordering in the data source for large datasets.

@GetMapping
public Page<CourseResponse> listCourses(
        @RequestParam(required = false) String department,
        @PageableDefault(size = 20, sort = "title")
        Pageable pageable) {
    return courseService.search(department, pageable);
}

Spring Data Web support can resolve a Pageable from parameters such as ?page=0&size=20&sort=title,asc when the relevant Spring Data dependency is present. Configure maximum page size and allowlist sort properties so clients cannot request excessive data or arbitrary persistence fields.

7. Test a GET API

Test the observable contract: status code, JSON fields, empty results, missing resources, filters, and validation. A @WebMvcTest with MockMvc can focus on the web layer.

@WebMvcTest(CourseController.class)
class CourseControllerTest {
    @Autowired
    MockMvc mockMvc;

    @MockitoBean
    CourseService courseService;

    @Test
    void returnsCourseById() throws Exception {
        when(courseService.findById(42L))
                .thenReturn(Optional.of(new CourseResponse(
                        42L, "CS336B", "OOPS with Java", 4, "CS")));

        mockMvc.perform(get("/api/courses/42")
                .accept(MediaType.APPLICATION_JSON))
            .andExpect(status().isOk())
            .andExpect(jsonPath("$.code").value("CS336B"));
    }
}

The @MockitoBean annotation is available in recent Spring Framework versions; projects on older Spring Boot versions may use that version’s supported mock-bean annotation. Add imports for JUnit, MockMvc, Mockito, and JSONPath from the project’s test starter.

8. Production considerations

  • Keep GET read-only: do not trigger updates or irreversible actions from retrieval endpoints.
  • Authorize every resource: knowing an ID does not grant access. Scope queries to the authenticated user or tenant when required.
  • Limit result size: do not return unbounded tables; use pagination and sensible maximums.
  • Avoid N+1 queries: inspect data access behavior when serializing collections and associations.
  • Control response fields: use DTOs and avoid exposing internal or sensitive data.
  • Use caching carefully: cache only when responses are safe to reuse and authorization context is handled correctly.
  • Use HTTPS: protect data in transit even when the endpoint only reads information.

Interview questions

  1. What does @GetMapping do?
    It maps HTTP GET requests matching its path and conditions to a controller handler method.
  2. Why should GET be safe and idempotent?
    Clients, proxies, and caches may repeat or prefetch GET requests; repeating a read should not cause additional state changes.
  3. What is the usual response when a single requested resource is absent?
    404 Not Found.
  4. What should an empty collection endpoint return?
    Usually 200 OK with an empty collection, since the collection resource exists even when it has no matching items.
  5. Why use a service between controller and repository?
    It keeps HTTP concerns separate from use-case logic and data-access concerns.
  6. How should a large collection be exposed?
    With bounded pagination and filtering applied at the data source, not by returning the entire dataset.
