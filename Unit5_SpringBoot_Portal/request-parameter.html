Request Parameters in Spring Boot

Read filters, pagination, sorting, and optional values from the URL query string with Spring MVC.

← Previous: Path Variable Unit 5 Home Next: GET API →

Learning outcomes

After this lesson, you should be able to bind query-string values with @RequestParam, configure optional parameters and defaults, handle repeated parameters and conversion, validate user-supplied values, and design testable collection endpoints.

Use query parameters to refine a request. In /api/courses?department=CS&page=0, the path identifies the collection and the query parameters filter or paginate it.

1. Anatomy of a query string

Query parameters begin after ?. Each name-value pair is separated by &. The query string modifies the request; it is not part of the resource path.

2. Basic @RequestParam usage

Spring MVC binds request parameters to method arguments by name. A request parameter is required by default. Names are clearer and more robust when explicitly declared.

@RestController
@RequestMapping("/api/courses")
public class CourseController {
    private final CourseService courseService;

    public CourseController(CourseService courseService) {
        this.courseService = courseService;
    }

    @GetMapping
    public List<CourseResponse> search(
            @RequestParam("department") String department) {
        return courseService.findByDepartment(department);
    }
}

Request example:

GET /api/courses?department=CS

The query parameter name and the annotation name must match. If it is required and absent, Spring rejects the request before invoking the controller (typically with 400 Bad Request).

3. Optional parameters and defaults

Use required = false when omission is meaningful, or use defaultValue when the endpoint has a sensible default. Specifying defaultValue also makes the parameter non-required.

@GetMapping
public Page<CourseResponse> search(
        @RequestParam(required = false) String department,
        @RequestParam(defaultValue = "0") int page,
        @RequestParam(defaultValue = "20") int size) {
    return courseService.search(department, page, size);
}
  • ?department=CS&page=0&size=20 supplies all values.
  • ?page=1 leaves department absent and uses the default size.
  • @RequestParam(required = false) String department binds a missing value to null.
  • Defaults should be documented and limits enforced; a client should not be able to request an unbounded page accidentally.
Be careful with primitives: a primitive such as int cannot represent null. Use a wrapper such as Integer for an optional value without a default, or supply a default value.

4. Type conversion and repeated values

Request parameters arrive as text. Spring MVC converts them to common Java types such as numbers, booleans, enums, dates, and collections. Conversion failures usually result in 400 Bad Request.

public List<CourseResponse> filter(
        @RequestParam(required = false) CourseLevel level,
        @RequestParam(required = false) List<String> tag,
        @RequestParam(defaultValue = "false") boolean active) {
    return courseService.filter(level, tag, active);
}

A request can include repeated parameter names:

GET /api/courses?tag=java&tag=spring&active=true

Here, Spring can bind the repeated tag values to a list. A comma-separated string such as ?tag=java,spring is a different representation; use it only if the API documents that format and the chosen conversion behavior is understood.

5. Validate parameter values

Binding converts a string but does not enforce business limits. Validate pagination, ranges, and formats before using them. For controller method parameter constraints, use Jakarta Validation constraints and activate method validation as required by the Spring Boot version and application setup.

import jakarta.validation.constraints.Max;
import jakarta.validation.constraints.Min;
import org.springframework.validation.annotation.Validated;

@RestController
@Validated
@RequestMapping("/api/courses")
public class CourseController {
    @GetMapping
    public Page<CourseResponse> list(
            @RequestParam(defaultValue = "0")
            @Min(0) int page,
            @RequestParam(defaultValue = "20")
            @Min(1) @Max(100) int size) {
        return courseService.list(page, size);
    }
}

With the validation starter present, method parameter constraints are checked when method validation is enabled. Confirm the exact activation behavior for your Spring Boot/Spring Framework version. Invalid values should produce a documented client error, not be silently clamped unless that behavior is explicitly part of the API contract.

7. URL encoding and API design

Query strings are part of a URL and must be encoded correctly. Reserved characters, spaces, and non-ASCII text should be percent-encoded by a URL builder or HTTP client rather than concatenated manually.

  • Use query parameters for filtering, pagination, sorting, search, and optional representation controls.
  • Use a stable resource path for the collection or item, such as /api/courses.
  • Set a maximum page size and validate sort fields against an allowlist; never pass arbitrary client values into SQL or dynamic query fragments.
  • Do not put passwords, tokens, or other secrets in query strings. URLs can be retained in browser history, proxy logs, analytics, and referrer data.
  • Document whether filters are case-sensitive, how repeated parameters behave, and what happens for unknown or invalid values.

8. Call the endpoint

A query string can be sent directly in the request URL:

curl -G "http://localhost:8080/api/courses" \
  --data-urlencode "department=Computer Science" \
  --data-urlencode "page=0" \
  --data-urlencode "size=20"

--data-urlencode safely encodes values such as those containing spaces. In browser-based clients, use the URL or query-parameter builder rather than manually joining raw values.

9. Test request parameters

Controller tests should cover provided, omitted, invalid, repeated, and boundary values. A MockMvc test can verify the public contract without starting a network server.

mockMvc.perform(get("/api/courses")
        .param("department", "CS")
        .param("page", "0")
        .param("size", "20"))
    .andExpect(status().isOk())
    .andExpect(jsonPath("$.content").isArray());

mockMvc.perform(get("/api/courses")
        .param("page", "-1"))
    .andExpect(status().isBadRequest());

Also test default behavior when parameters are absent, maximum page-size enforcement, conversion errors, and repeated parameter handling. Assert stable statuses and response shapes, not internal exception messages.

Interview questions

  1. What does @RequestParam bind?
    It binds a query or form request parameter to a controller method argument.
  2. Are request parameters required by default?
    Yes. Use required = false or defaultValue when omission is allowed.
  3. How do you receive repeated query parameters?
    Bind them to a collection such as List<String> and send repeated names, for example ?tag=java&tag=spring.
  4. What is the difference between @RequestParam and @PathVariable?
    Request parameters refine a request; path variables identify a resource in the URI path.
  5. Why should page size be limited?
    To prevent accidental or abusive requests from returning too much data and consuming excessive resources.
  6. Why should secrets not be put in a query string?
    URLs are commonly retained in logs, history, monitoring, and referrer information.
