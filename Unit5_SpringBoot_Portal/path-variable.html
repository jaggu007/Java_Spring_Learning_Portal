Path Variables in Spring Boot

Capture resource identifiers from a URI path and bind them to strongly typed Spring MVC handler parameters.

← Previous: Request Body Unit 5 Home Next: Request Parameter →

Learning outcomes

After this lesson, you should be able to define path-variable mappings, bind one or more URI segments, convert identifiers to Java types, distinguish path variables from query parameters, and handle invalid or missing resources appropriately.

Use a path variable to identify a resource. In /api/courses/42, 42 identifies the course. Use query parameters for optional filters, pagination, sorting, or other modifiers.

1. What is a path variable?

A path variable is a named value embedded in a URI path. In Spring MVC, curly braces declare a variable in a mapping, and @PathVariable binds the captured segment to a handler method parameter.

2. Basic usage

Declare a variable in the path mapping and annotate the corresponding parameter. Use an explicit annotation name when it improves readability or avoids reliance on Java parameter-name metadata.

@RestController
@RequestMapping("/api/courses")
public class CourseController {
    private final CourseService courseService;

    public CourseController(CourseService courseService) {
        this.courseService = courseService;
    }

    @GetMapping("/{courseId}")
    public CourseResponse getCourse(
            @PathVariable("courseId") long id) {
        return courseService.findById(id);
    }
}

The class-level mapping and method-level mapping combine to produce /api/courses/{courseId}. A request to GET /api/courses/42 captures the text 42, converts it to long, and invokes the handler.

3. Multiple path variables

Nested resources can contain more than one variable. Each variable name in the path should correspond to a handler argument.

@GetMapping("/{courseId}/students/{studentId}")
public StudentResponse getStudentInCourse(
        @PathVariable long courseId,
        @PathVariable long studentId) {
    return courseService.findStudent(courseId, studentId);
}

This maps GET /api/courses/42/students/7 and binds courseId to 42 and studentId to 7. The service should also verify that student 7 belongs to course 42; capturing two IDs does not enforce that relationship.

You may use explicit names where parameter-name inference is uncertain:

public StudentResponse getStudentInCourse(
        @PathVariable("courseId") long course,
        @PathVariable("studentId") long student) {
    return courseService.findStudent(course, student);
}

4. Type conversion and identifier types

Path values arrive as text and Spring MVC converts them to the declared parameter type using its conversion infrastructure. Common target types include String, numeric primitives/wrappers, UUID, and supported date/time types.

@GetMapping("/by-key/{key}")
public CourseResponse findByKey(@PathVariable UUID key) {
    return courseService.findByKey(key);
}
  • A numeric route such as /api/courses/abc cannot be converted to long; Spring returns a client error (commonly 400 Bad Request).
  • A syntactically valid identifier can still refer to no resource; the service should report that as a not-found condition, typically mapped to 404 Not Found.
  • Use wrapper types such as Long only when a value can legitimately be absent; path segments in a matched route are generally present.
  • For domain-specific identifier formats, consider a validated value object or an explicit converter rather than parsing inconsistently in every controller.

5. Constrain path patterns

When an endpoint needs a constrained segment, a path pattern can restrict what it matches. For example, a numeric expression avoids matching alphabetic values as a course ID route:

@GetMapping("/{courseId:[0-9]+}")
public CourseResponse getCourse(
        @PathVariable long courseId) {
    return courseService.findById(courseId);
}

Pattern constraints help route selection, but they do not replace business validation or authorization. Keep route patterns readable and avoid complex regular expressions that are difficult for clients and maintainers to understand.

Static routes and variable routes

@GetMapping("/featured")
public List<CourseResponse> featuredCourses() {
    return courseService.findFeatured();
}

@GetMapping("/{courseId}")
public CourseResponse getCourse(
        @PathVariable long courseId) {
    return courseService.findById(courseId);
}

Design static paths and variable paths together. A constrained numeric variable can help distinguish /featured from an ID route, but prefer clear, non-overlapping route designs over depending on subtle matching details.

@GetMapping
public Page<CourseResponse> searchCourses(
        @RequestParam(required = false) String department,
        @RequestParam(defaultValue = "0") int page,
        @RequestParam(defaultValue = "20") int size) {
    return courseService.search(department, page, size);
}

Use /courses/{id} to select one course; use /courses?department=CS to filter the collection.

7. Validate and authorize identifiers

Binding a value only proves it could be converted to the Java type. It does not prove that the resource exists or that the caller may access it.

  1. Syntax: ensure the segment can be converted or matches a required format.
  2. Existence: look up the resource and return a not-found response when it does not exist.
  3. Relationship: verify nested identifiers belong together, such as a student belonging to the requested course.
  4. Authorization: check whether the authenticated caller may access or modify that specific resource.

For more complex validation, use a service or domain method so the same rules apply to every entry point. Do not rely on obscurity of sequential IDs as an access-control mechanism.

9. Test path-variable behavior

Controller tests should cover a valid identifier, a resource that does not exist, an invalid identifier format, and nested-resource relationships where applicable.

mockMvc.perform(get("/api/courses/42")
        .accept(MediaType.APPLICATION_JSON))
    .andExpect(status().isOk())
    .andExpect(jsonPath("$.id").value(42));

mockMvc.perform(get("/api/courses/not-a-number"))
    .andExpect(status().isBadRequest());

MockMvc test setup and exact error bodies depend on the application’s controller advice and framework version. Assert the public status and response contract rather than framework-specific conversion exception text.

Interview questions

  1. What does @PathVariable do?
    It binds a variable captured from the URI path to a controller method parameter.
  2. How does Spring convert a path segment to a number?
    Spring MVC’s conversion infrastructure converts the textual path value to the declared Java type; conversion failure becomes a client error.
  3. When should a path variable be used instead of a query parameter?
    Use a path variable to identify the resource; use a query parameter for optional collection filters and modifiers.
  4. Does a valid path variable guarantee the resource exists?
    No. Conversion only validates representation; application logic must perform the lookup.
  5. Does knowing a resource ID grant access to it?
    No. Authorization must be checked for the authenticated caller and the specific resource.
  6. How do you bind multiple path variables?
    Declare each named segment in the mapping and bind each with a matching @PathVariable parameter.
